# Cloud task startup

Use the existing `/workspace/landslide` checkout. Each task is already isolated; do not create a Git worktree unless the user explicitly requests one.

Prepared dependencies live in `node_modules` and `backend/.venv`. If missing or changed, run `cd /workspace/landslide && bash scripts/setup.sh --demo`. This uses frozen dependency locks, starts PostgreSQL/PostGIS, waits for readiness, applies the migration and seeds explicitly synthetic records. It creates no user accounts or predictions. Preserve existing database volumes, local files and user changes; never reset the checkout or delete the volume to start a task.

Processes are not assumed to survive environment publication. From `/workspace/landslide`, run `docker compose up -d db` and verify `docker compose exec -T db pg_isready -h 127.0.0.1 -U ashtaraksha -d ashtaraksha`. Apply `cd backend && .venv/bin/python manage.py migrate` if required, then return to the root and run `npm run dev:all` in a persistent terminal. Verify a GET to `http://127.0.0.1:8000/health` returns status ok, database PostgreSQL and a PostGIS version; GET `http://127.0.0.1:5173/login` must return the application shell. Use these addresses for internal checks, not user-facing preview links. Ctrl+C stops API/frontend; the database container is retained.

For the PWA, run `npm run build`, keep the API on 8000, and run `npm run preview -- --host 127.0.0.1 --port 4173` instead of Vite development mode. The worker caches the shell/assets and the public-domain regional reference map; reports and attachment files use an author-scoped IndexedDB queue. Do not cache private API responses or bulk-cache OpenStreetMap tiles.

There are no default application passwords. Register through the app; bootstrap an admin through the documented local management command, then use Administration to assign roles. Both supplied model versions and fitted pipelines are in the backend-local handoff archive; V1 is default and V2 experimental. No training occurs. See `docs/MODEL_INTEGRATION.md` for the exact environmental feature contracts, null policy and relative-score limitations. Sensor, population, historical and seeded weather values are labelled synthetic.

Live weather requires outbound access to `api.open-meteo.com`; optional online street tiles require `tile.openstreetmap.org` (or configured CARTO). The bundled regional reference needs no external tile access. In this onboarding environment the forecast domain was denied by policy; do not disable TLS or claim a live feed. Preserve unknown existing network rules when requesting additions. The app retains sample/cache data and reports refresh failures.

Validation: `npm run build`; `backend/.venv/bin/python -m pytest tests/test_api.py -q` against the isolated `_test` database; `npm run test:e2e` against the separate `_e2e_test` database. Stop development servers before Playwright, which owns ports 8000/4173 during the test. Never point truncating test fixtures at the development database. See README for test-database creation. Requirements, data provenance and deployment limitations are documented in `docs/`.

For the user's own-data workflow, use `npm run dev:clean` instead of `npm run dev:all`. It selects the separate unseeded local `ashtaraksha_clean` database, preserving the original database. Do not seed demo data into it. See `CLEAN_START.md` for role promotion with the correct database override.
